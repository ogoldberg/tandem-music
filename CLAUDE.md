# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Tandem is an experimental-alpha browser music collaborator (sing/hum/beatbox -> editable notes/drums -> AI-assisted arrangement). Read `docs/PRODUCT.md` before changing scope; `docs/ARCHITECTURE.md`, `docs/AUDIO.md`, `docs/DEVELOPMENT.md`, `docs/TESTING.md`, `docs/SECURITY.md`, `docs/ROADMAP.md` and `docs/DECISIONS.md` (ADRs) hold the details. Update the relevant doc whenever behavior or scope changes.

## Commands

Python 3.12 (`.python-version`) and Node 22+.

```bash
python3.12 -m venv .venv && source .venv/bin/activate
python -m pip install -r requirements-dev.txt

# Run app (UI + API on one origin, no separate frontend server or build step)
uvicorn tandem_backend:app --reload --host 127.0.0.1 --port 8000

# Tests (backend and Node tests run in CI; the e2e suite below runs as its own CI job: .github/workflows/tests.yml)
python -m pytest -q
python -m pytest tests/test_api.py::test_token_auth -q     # single Python test
node --test tests/transcription.test.mjs tests/polish.test.mjs tests/tuning.test.mjs tests/history.test.mjs tests/versions.test.mjs tests/contour.test.mjs tests/groove.test.mjs tests/voices.test.mjs tests/harmony.test.mjs tests/phrases.test.mjs tests/storage.test.mjs tests/recordings.test.mjs tests/samples.test.mjs tests/ideas.test.mjs tests/bundle.test.mjs tests/daw.test.mjs
node --test --test-name-pattern="resampl" tests/transcription.test.mjs  # single Node test

# Browser end-to-end (Playwright, headless Chromium; not collected by plain `pytest`)
python -m pip install -r requirements-e2e.txt && python -m playwright install chromium
python -m pytest e2e -q
```

There is no linter or formatter configured.

## Architecture

- **No build step / no framework.** `index.html` is the entire studio UI (inline script, Web Audio, piano roll, playback, WAV/MIDI export). It lazy-imports `transcription.js` (ES module) which loads the self-hosted Spotify Basic Pitch bundle and model from `/vendor/basic-pitch-1.0.1/` (built by `tools/basic-pitch/build.sh`, hashes in its `SHA256SUMS`, served by an allowlisted route in `tandem_backend.py`), resamples to 22,050 Hz (`resampleForBasicPitch`) and converts output to the project schema. It also lazy-imports `polish.js` (on-device vocal polish: band-pass EQ/gate/compression only, never pitch; a sample-exact port of the old server DSP). The Tune button lazy-imports `tuning.js`, which splits recordings longer than 16 s into overlapping chunks for `/api/tune` (each request stays under the 25 s cap and Vercel's 4.5 MB body limit), retries 429s after `Retry-After`, and joins the chunks with short crossfades at the quietest point of each overlap. The inline script is a `type="module"` script that statically imports `history.js` (EDIT.1): bounded undo/redo over JSON snapshots of the project plus the vocal tuning targets, with labels, no-op detection and `rewrite` (used to drop a replaced recording's targets). It also statically imports `contour.js` (VOX.3 pitch-contour editor model: sung pitch line from Basic Pitch's contour, fragment merging, key/scale snapping, correction preview that mirrors `world_tuning._target_notes`; checked against the server via `tests/fixtures/target-correction.json`). Every edit in `index.html` goes through `edit(label, fn)`; never mutate `state` or `vocalNotes` outside it. It also statically imports `groove.js` (ARR.1a tempo detection and quantize with swing) and `voices.js` (ARR.1b melody instrument voices: `playNote` builds layered oscillators, envelope, filter and vibrato for both playback and WAV export; its `INSTRUMENTS` list must match the `INSTRUMENTS` tuple in `tandem_backend.py`, which a Node test checks) and `harmony.js` (ARR.1c key detection and chord/bass accompaniment generation) and `phrases.js` (ARR.1d phrase detection and phrase move/copy/transpose) and `storage.js` (STORE.2a: the draft and named versions in IndexedDB via a small key-value store, migrated from the old `localStorage` keys on every start; the draft is written on every `update()`, but only after the stored draft has been read at start-up) and `recordings.js` (STORE.2a: the original, polished and tuned recordings as files in the Origin Private File System named by SHA-256; the draft links them under the `draft-audio` key, never inside the project, and each version keeps its own links; unlinked files are collected under an exclusive Web Lock). It also statically imports `samples.js` (SND.1: melody, harmony and drums play recorded General MIDI samples rendered from the MIT-licensed FluidR3_GM SoundFont by `tools/gm-samples/build.py` and self-hosted at `/vendor/gm-samples-1/`, an allowlisted route serving only the files in its `SHA256SUMS`; the same `playSample` schedules playback and the WAV export, and a part whose samples are missing or still loading plays its `voices.js` oscillator voice; `LEVELS` must list exactly the `INSTRUMENTS`, which a Node test checks). It also statically imports `ideas.js` (MOB.1: song ideas captured on the phone, a list under the `ideas` key next to the draft and versions, each linking one recording in OPFS); the studio's recording clean-up must keep every idea's recording, and `?idea=<id>` opens an idea as a new draft after saving a non-empty draft as a version. It also statically imports `daw.js` (EXP.1: Export MIDI writes a type-1 file with a conductor track (tempo, 4/4, key) and named Melody/Harmony/Drums tracks; Export stems downloads a zip of one WAV per part and recorded vocal, mono 44.1 kHz from zero and the same length, `mix.wav` and the MIDI; each part renders on its own and Export WAV is their sum, so the stems line up with it; `PROGRAMS` must match the sample manifest's programs, which a Node test checks). It also statically imports `bundle.js` (MOB.3: an idea or project as one `.tandem.zip` file, `tandem.json` + `project.json` + `original.wav`/`polished.wav`/`tuned.wav`, the DESK.3 project folder zipped; the capture page's Share writes it, the studio's Open project reads it with its recordings; written stored, read stored or deflated). `capture.html` (served at `/capture`, with its own `capture.webmanifest` so adding it to the home screen opens capture) is the phone capture page: one record button, every take kept at once through `recordings.js` and `ideas.js`, ideas played, renamed, deleted and opened in the studio. These modules are imported directly by the Node tests, so keep their exports pure/testable.
- **FastAPI serves everything.** `tandem_backend.py` explicitly routes `/`, `/sw.js`, `/transcription.js`, `/polish.js`, `/tuning.js`, `/history.js`, `/versions.js`, `/groove.js`, `/voices.js`, `/harmony.js`, `/phrases.js`, `/storage.js`, `/recordings.js`, `/samples.js`, `/contour.js`, `/ideas.js`, `/bundle.js`, `/daw.js`, `/capture` (`capture.html`), `/manifest.webmanifest`, `/capture.webmanifest`, and the four PNG app icons under `/icons/` (MOB.2, allowlisted in `ICON_FILES`; rendered from `icons/*.svg` by `tools/icons/build.py`) via `FileResponse` — a new static frontend file needs its own route here (there is no static mount). `sw.js` caches same-origin GETs (not `/api/`) and precaches `history.js`, `versions.js`, `groove.js`, `voices.js`, `harmony.js`, `phrases.js`, `storage.js`, `recordings.js`, `samples.js`, `contour.js`, `ideas.js`, `bundle.js` and `daw.js` because the page's module script imports them statically and cannot start without them, plus the capture page, both manifests and the icons, so both pages open offline (MOB.2); `/vendor/` files are cached on first use in a separate `tandem-vendor-1` cache that survives `CACHE` bumps (bump `VENDOR` when a vendor directory moves); bump `CACHE` when stale-asset issues matter.
- **Mac app (DESK.1):** `python -m tandem_desktop` (needs `requirements-desktop.txt`, pywebview) runs `tandem_backend.app` on `127.0.0.1` at a port chosen once and kept in `~/Library/Application Support/Tandem/desktop.json` (the origin owns the IndexedDB/OPFS data, so never change the port silently), wrapped by `guarded_app`, which answers 421 unless `Host` is exactly `127.0.0.1:<port>`, and opens it in a pywebview/WKWebView window whose microphone requests are answered by `allow_media` (own origin, microphone only). DESK.2: each launch makes a secret that `launch_script` gives only to the window's own-origin page (`window.tandemLaunch`); `guarded_app` refuses `/api/` without it in the `x-tandem-launch` header and any foreign `Origin`, and marks passing requests `scope["tandem_local"]`, which alone lifts the hosted limits (`request_guards.is_local`, `limits_for` in `tandem_backend.py`: no rate limit, 600 s and 4096 targets per audio request). `tandem_desktop/__init__.py` must not import pywebview, so CI can test it on Linux; `/api/config` reports `runtime` `desktop` there and `web` elsewhere. AI.4: `tandem_desktop/ai_keys.py` (`AISettings`, passed to `guarded_app` as `ai_settings`) serves `/api/desktop/ai` (GET/PUT) and `/api/desktop/ai/key` (DELETE) there: the provider and model in `ai.json` in the settings folder, the key only in the macOS Keychain via `keyring` (imported lazily; tests use a stand-in store); the page learns only `has_key`, never the key. `guarded_app` also sets `scope["tandem_ai"]`, which `llm_config(request)` in `tandem_backend.py` honours only when `is_local`, so `/api/chat` uses the person's provider with the unchanged `invoke_llm(messages, config)`, `normalize_actions` and melody lock; with nothing saved the `TANDEM_*` env applies. DESK.3: `tandem_desktop/projects.py` (`ProjectFolders`, passed to `guarded_app` as `desktop_api`) serves `/api/desktop/project/save|open` only there: the page sends and gets a project as the `bundle.js` Tandem file, and the server writes and reads it as a folder (the same file names) the person picked in the window's native dialog (`WindowDialogs`). MODEL.1: `tandem_desktop/models.py` (`ModelRuntime`, passed to `guarded_app` as `models`) downloads large audio models on request into `models/<id>/` in the settings folder, keeps a file only when its pinned size and SHA-256 match, hashes it again before loading, and runs downloads and model runs as background jobs with progress, cancel and errors (`/api/desktop/models`, `/api/desktop/jobs/<id>`); `/api/config` reports `models_installed`. Its `CATALOG` is empty until SEP.1; model packages go in `requirements-models.txt`, never `requirements.txt`, and the hosted app must never import the module (a test checks). SEP.1: `tandem_desktop/separation.py` (`Separation`, passed to `guarded_app` as `separation`) runs Demucs' htdemucs (`models.HTDEMUCS`, safetensors from Hugging Face, loaded without pickle and only as HTDemucs) at `/api/desktop/separate`; the studio's Separate keeps the stems in the `vocal` and `accompaniment` recording slots, and `take()` (`vocal ?? audio`) is what Transcribe, Polish, Detect and Tune work on. Real-model tests are marked `model` and need `TANDEM_TEST_MODEL_HOME` (the `separation` CI job sets `TANDEM_REQUIRE_SEPARATION=1`). GEN.2: `tandem_desktop/band.py` (`Band`, passed to `guarded_app` as `band`) runs MusicGen-Melody (`models.MUSICGEN_MELODY`, transformers from safetensors only, weights CC-BY-NC 4.0) at `/api/desktop/band`; the studio's Band track keeps the description in the optional project field `band` (`ProjectBand`, no AI action edits it) and the audio in the `band` recording slot, looked up by `band.id` in the page's `bands` map so undo finds it; the band is a part stem and in the mix unless muted. Its real-model test needs `TANDEM_TEST_BAND=1` too (6.23 GB, not in CI).
- **Vercel deploy:** `api/index.py` just re-exports `tandem_backend.app`; pushes to `main` deploy to production (https://tandem-music.vercel.app). `vercel.json` sets `maxDuration: 60` and excludes tests. A READY build is not evidence that tests pass or audio quality is acceptable.
- **API routes:** `/api/health`, `/api/config` (non-secret capability metadata), `/api/chat` (LLM), `/api/analyze` (heuristic autocorrelation melody + onset drums fallback), `/api/tune` (pitch correction via `world_tuning.world_tune`, WORLD vocoder from `pyworld-prebuilt`; WAV only, <=25 s; optional `notes_json` targets, `vibrato` 0..1 and `scale` pitch classes).
- **Auth/spend guard:** an HTTP middleware protects only `/api/chat` with the `x-tandem-token` header vs `TANDEM_ACCESS_TOKEN`; when `VERCEL` is set and no token is configured, chat fails closed with 503. Audio routes are public but rate-limited per client IP by `RequestGuardMiddleware` (`request_guards.py`), which also caps body sizes for audio routes and `/api/chat`; on Vercel the counters live in Upstash Redis and audio routes fail closed with 503 when the store is unset or failing.
- **LLM flow:** `invoke_llm` is a hand-rolled httpx adapter for `openai-compatible` (default; also ollama), `anthropic`, and `gemini`, chosen by `TANDEM_PROVIDER`/`TANDEM_MODEL`/`TANDEM_API_KEY`/`TANDEM_BASE_URL`. The model must return JSON `{reply, actions}`; `extract_json` parses it, `normalize_actions` allowlists action types and clamps values, and melody lock (default on, ADR-004) strips `transpose`/`add_note`/`replace_notes`/melody `remove_track`. The browser applies validated actions with undo. Provider keys stay server-side only.
- **Project schema** (portable JSON, no audio embedded; `/api/chat` validates it with the `ChatProject` pydantic model, extra keys forbidden): `{"format":"tandem-project","version":1,"bpm","instrument","melody_locked","notes":[{m,t,d}],"drums":[{k,t}],"harmony":[{m,t,d}],"harmony_instrument"}` — `m` MIDI pitch, `t`/`d` seconds, `k` in kick/snare/hat. `harmony`/`harmony_instrument` (ARR.1c) are optional: older projects without them open with no harmony on piano, and no AI action edits them. Keep frontend, `normalize_actions`, and `/api/tune` note validation consistent with it.
- **Storage is stateless** (ADR-006): there is no server-side database; Vercel filesystems are ephemeral.
- `TANDEM_MUSIC_PROVIDER`/`TANDEM_MUSIC_MODEL` are reserved metadata only; no music-generation adapter exists.

## Testing conventions

- `tests/test_api.py` drives the ASGI app in-process with `httpx.ASGITransport` (no server needed), uses `monkeypatch` for env vars, and builds synthetic WAVs with `wav_bytes`. LLM providers are mocked — never call real paid APIs in tests.
- Node tests mock `OfflineAudioContext`.
- `e2e/` tests start uvicorn on a free port (TANDEM_/VERCEL/UPSTASH_ env stripped) and fail on any page error or `console.error`; they use the server fallback transcriber so they need no CDN.
- Docs are deliberate about "implemented vs planned" and "unverified" device QA status; don't describe features as working or verified without real evidence (see `docs/TESTING.md` release gate).
