# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Tandem is an experimental-alpha browser music collaborator (sing/hum/beatbox -> editable notes/drums -> AI-assisted arrangement). Read `docs/PRODUCT.md` before changing scope; `docs/ARCHITECTURE.md`, `docs/AUDIO.md`, `docs/DEVELOPMENT.md`, `docs/TESTING.md`, `docs/SECURITY.md`, `docs/ROADMAP.md` and `docs/DECISIONS.md` (ADRs) hold the details. Update the relevant doc whenever behavior or scope changes.

## Commands

Python 3.12 (`.python-version`) and Node 22+.

```bash
python3.12 -m venv .venv && source .venv/bin/activate
python -m pip install -r requirements-dev.txt

# Run app (UI + API on one origin, no separate frontend server or build step)
uvicorn tandem_backend:app --reload --host 127.0.0.1 --port 8000

# Tests (backend and Node tests run in CI; the e2e suite below runs as its own CI job: .github/workflows/tests.yml)
python -m pytest -q
python -m pytest tests/test_api.py::test_token_auth -q     # single Python test
node --test tests/transcription.test.mjs tests/polish.test.mjs tests/tuning.test.mjs tests/history.test.mjs tests/versions.test.mjs tests/contour.test.mjs tests/groove.test.mjs tests/voices.test.mjs tests/harmony.test.mjs tests/phrases.test.mjs tests/storage.test.mjs tests/recordings.test.mjs tests/samples.test.mjs tests/ideas.test.mjs tests/bundle.test.mjs tests/daw.test.mjs tests/notation.test.mjs tests/dawproject.test.mjs tests/worldtune.test.mjs tests/midi.test.mjs tests/noteedit.test.mjs tests/guide.test.mjs tests/playhead.test.mjs tests/evolution.test.mjs tests/take.test.mjs tests/pitch.test.mjs tests/beats.test.mjs tests/latency.test.mjs tests/mixer.test.mjs tests/layers.test.mjs tests/takes.test.mjs tests/sections.test.mjs tests/tension.test.mjs tests/drawline.test.mjs tests/lyrics.test.mjs tests/genre.test.mjs tests/practice.test.mjs tests/exercises.test.mjs tests/beatbox.test.mjs tests/actions.test.mjs tests/bars.test.mjs tests/longsong.test.mjs tests/placement.test.mjs tests/tap.test.mjs tests/shape.test.mjs
node --test --test-name-pattern="resampl" tests/transcription.test.mjs  # single Node test

# Browser end-to-end (Playwright, headless Chromium; not collected by plain `pytest`)
python -m pip install -r requirements-e2e.txt && python -m playwright install chromium
python -m pytest e2e -q
```

There is no linter or formatter configured.

Dependencies (SEC.9): edit `requirements*.in`, then `sh tools/locks/compile.sh` (uv) writes the hashed `requirements*.txt` locks that every install reads (Vercel installs `requirements.txt`); CI audits every lock with pip-audit and pins actions to commit SHAs (`tests/test_locks.py`).

## Architecture

- **No build step / no framework.** `index.html` is the entire studio UI (inline script, Web Audio, piano roll, playback, WAV/MIDI export). It lazy-imports `transcription.js` (ES module) which loads the self-hosted Spotify Basic Pitch bundle and model from `/vendor/basic-pitch-1.0.1-2/` (built by `tools/basic-pitch/build.sh`, hashes in its `SHA256SUMS`, served by an allowlisted route in `tandem_backend.py`), resamples to 22,050 Hz (`resampleForBasicPitch`) and converts output to the project schema. It also lazy-imports `polish.js` (on-device vocal polish: band-pass EQ/gate/compression only, never pitch; a sample-exact port of the old server DSP). The studio statically imports `tuning.js` (HARM.3; it was lazy-imported by Tune before), which splits recordings longer than 16 s into overlapping chunks for `/api/tune` (each request stays under the 25 s cap and Vercel's 4.5 MB body limit), retries 429s after `Retry-After`, and joins the chunks with short crossfades at the quietest point of each overlap. VOX.4: by default each chunk is tuned on the device instead (`tune` option): `tuneworker.js` runs `worldtune.js`, a line-for-line port of `world_tuning.py` on WORLD compiled to WebAssembly (`vendor/world-d625e76-1/`, built by `tools/world-wasm/build.sh` with Emscripten 7.0.0 from the WORLD commit pyworld 0.3.6 uses, allowlisted route, hashes in `SHA256SUMS`); `tests/test_vocal_benchmark.py` runs every VOX.1 check on both engines and checks they give the same audio. The inline script is a `type="module"` script that statically imports `history.js` (EDIT.1): bounded undo/redo over JSON snapshots of the project plus the vocal tuning targets, with labels, no-op detection and `rewrite` (used to drop a replaced recording's targets); UX.6: `markHistory`/`editsSince` count a guided change view's edits for its Before / After (Before plays the project as the view opened through `playback({src})`) and Put it back (that many Undo steps). It also statically imports `contour.js` (VOX.3 pitch-contour editor model: sung pitch line from Basic Pitch's contour, fragment merging, key/scale snapping, correction preview that mirrors `world_tuning._target_notes`; checked against the server via `tests/fixtures/target-correction.json`; TRANS.2: `sungNotes` builds the Transcribe melody from the sung line, so a note lasts as long as its pitch is held and a slide joins the note it settles on). Every edit in `index.html` goes through `edit(label, fn)`; never mutate `state` or `vocalNotes` outside it. It also statically imports `groove.js` (ARR.1a tempo detection and quantize with swing) and `voices.js` (ARR.1b melody instrument voices: `playNote` builds layered oscillators, envelope, filter and vibrato for both playback and WAV export; its `INSTRUMENTS` list must match the `INSTRUMENTS` tuple in `tandem_backend.py`, which a Node test checks) and `harmony.js` (ARR.1c key detection and chord/bass accompaniment generation; HARM.4 `progression` chooses the chords as a progression over half bars that starts and ends on the tonic, voiced at or below the melody's lowest note in each bar; CHORD.1 `readChords` names the chords part's chords from its notes (no chord list is stored) for the symbols above the chords roll, and `changeChord` rewrites one chord's notes as one edit; HARM.2 `harmonyLines`: the harmony lines Create harmony offers for the harmony voice, tried in the roll and played before Keep writes one into `voice2` as one edit) and `phrases.js` (ARR.1d phrase detection and phrase move/copy/transpose) and `storage.js` (STORE.2a: the draft and named versions in IndexedDB via a small key-value store, migrated from the old `localStorage` keys on every start; the draft is written on every `update()`, but only after the stored draft has been read at start-up) and `recordings.js` (STORE.2a: the original, polished and tuned recordings as files in the Origin Private File System named by SHA-256; the draft links them under the `draft-audio` key, never inside the project, and each version keeps its own links; unlinked files are collected under an exclusive Web Lock; REC.1: `liveChannels`/`monoSamples` leave out a channel 60 dB below the loudest, used by the studio's `decoded()`, `daw.js` `monoOf` and `bundle.js` `toWav`, so a one-sided microphone's stereo take plays in both ears and is read at full level). It also statically imports `samples.js` (SND.1: melody, harmony and drums play recorded General MIDI samples rendered from the MIT-licensed FluidR3_GM SoundFont by `tools/gm-samples/build.py` and self-hosted at `/vendor/gm-samples-1/`, an allowlisted route serving only the files in its `SHA256SUMS`; the same `playSample` schedules playback and the WAV export, and a part whose samples are missing or still loading plays its `voices.js` oscillator voice; `LEVELS` must list exactly the `INSTRUMENTS`, which a Node test checks). It also statically imports `ideas.js` (MOB.1: song ideas captured on the phone, a list under the `ideas` key next to the draft and versions, each linking one recording in OPFS); the studio's recording clean-up must keep every idea's recording, and `?idea=<id>` opens an idea as a new draft after saving a non-empty draft as a version. It also statically imports `daw.js` (EXP.1: Export MIDI writes a type-1 file with a conductor track (tempo, 4/4, key) and named Melody/Harmony/Drums tracks; Export stems downloads a zip of one WAV per part and recorded vocal, mono 44.1 kHz from zero and the same length, `mix.wav` and the MIDI; each part renders on its own and Export WAV is their sum, so the stems line up with it; MIX.2: Export WAV, Share the song and Export stems level the mix and every part and layer stem by one gain (`levelExport`) so the loudest peaks at -1 dB, raised at most 18 dB, said in the status by `levelLine`; the takes as recorded are left as they are; `PROGRAMS` must match the sample manifest's programs, which a Node test checks). ## Testing conventions

- `tests/test_api.py` drives the ASGI app in-process with `httpx.ASGITransport` (no server needed), uses `monkeypatch` for env vars, and builds synthetic WAVs with `wav_bytes`. LLM providers are mocked — never call real paid APIs in tests.
- Node tests mock `OfflineAudioContext`.
- `e2e/` tests start uvicorn on a free port (TANDEM_/VERCEL/UPSTASH_ env stripped) and fail on any page error or `console.error`; they use the server fallback transcriber, except the tests that run the self-hosted Basic Pitch model from `/vendor/` (detection, PERF.3, VOX.3 and TRANS.1's hummed melody), so they need no CDN.
- SEC.7: the pages' Content-Security-Policy has no `'unsafe-eval'`, so `e2e/conftest.py` replaces Playwright's `Page.wait_for_function` (which polls through a function built from a string in the page) with a requestAnimationFrame poll written into `page.evaluate`'s source; it honours `timeout=` and `arg=` (default 30 s), does not await an async predicate, and dies with a navigation, so wait across a reload with a fresh call after it.
- Docs are deliberate about "implemented vs planned" and "unverified" device QA status; don't describe features as working or verified without real evidence (see `docs/TESTING.md` release gate).
