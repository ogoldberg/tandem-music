## Task backlog

This is the working task list, in strategic order: protect the deployment, prove the core loop works on real devices, turn on the AI half of the product, then build a safety net before the larger editor work. Sections 1-5 are mostly done. Since ADR-013 (2026-11-10) phone capture comes first (section 5a): the web app installed on the phone catches song ideas and hands them to the studio as files. After it, since ADR-012 the open work is ordered for the biggest gain per unit of effort: first the quick audible win (sampled instruments), then the Mac app, which removes the hosted limits and is what lets Tandem run large audio models; then the AI half through the Mac app's own backend, hand-off to GarageBand and Logic, and the local audio models (sections 6 and 7). Since ADR-011 the product is local-first with the user's own storage and AI keys (section 8); the hosted AI path in section 3 is optional, and the web app stays as the zero-install and Android path. Loopkit's `/next-task` reads it (see `.agent-workflow.yml`). Format: `- [ ]` pending, `- [~]` in progress, `- [x]` done; the bold token is the task ID. `*(HUMAN)*` marks work that needs the owner: real devices, listening judgement, credentials, account settings or product decisions. Mark a task `[x]` only with evidence (CI run, recorded device result, merged PR). Real-device results (QA.1) may reorder the vocal and arrangement work.

- [ ] **HARM.4** Chords that go somewhere
  - Chords are chosen bar by bar with no sense of progression or ending: Twinkle gets I IV IV V and ends on V, Ode to Joy I seven times then V, jazz "I ii ii ii", and pop, rock and folk choose the same chords as no genre on six test tunes. The chords sit on top of a low hummed melody (fixed C3-G4 range, chords 52-60 under a melody at 48-55), and Thirds above leaps a seventh up and back for one note. A transition cost between bars (Viterbi over the bars), a pull to I on the last bar when its notes allow, half-bar changes where the fit is much better, genre priors that differ, chords voiced below the melody's lowest note, and leaps over a fourth costed heavily in the harmony lines.
  - **Acceptance:** Node tests on the six tunes (endings on I, every chord note at or below the melody's lowest note in its bar, no harmony leap over a fifth on a stepwise line, genres giving different progressions); judged by ear (HUMAN).
- [ ] **TEMPO.1** Tap the speed

- [ ] **BEAT.2** Drum fills at section ends

Older projects open unchanged; `beatbox.js` stays a line-for-line port of the server (fixture rerun).
  - **Acceptance:** Node and Python tests on recorded beatbox fixtures (per-kind accuracy over the current split, levels follow loudness), the beatbox server/device fixture still equal, MIDI export carries the velocities, an old project round-trips byte for byte; judged by ear (HUMAN).
- [ ] **SONG.3** An intro and an ending

Add ending holds the tonic chord under the last note with a final hit; Add intro puts one or two bars of drums and chords before the melody, moving the note parts and sections, and is refused while there is a recording (recordings are never moved, SONG.1). Both are one edit and mark an Intro or Outro section.

  - **Acceptance:** Node tests of the sheet model on a fixture; an e2e test of the rendered sheet; the MusicXML fixture regenerated and validated against the schema.

### 9e. Sing it to the chat (operator idea, 2026-11-20)
"Add a guitar line that goes like this", then hum it: the chat hears the hummed line, turns it into notes on the asked instrument, puts it in the right place in the song, and leaves it editable like any other part. The audio stays on the device: it is transcribed here (Basic Pitch, `contour.js` `sungNotes`) and the model gets the request and a description of the notes, never the recording.
- [ ] **CHAT.1** More than one note line: an instrument line as a part of its own
  - Today the note parts are fixed (melody, chords, harmony voice, drums), so "a guitar line" has nowhere to go but the melody. Optional project field `lines` `[{id, name, instrument, notes:[{m,t,d}]}]` (mirrored in `tandem_backend.py`), each a lane with its own roll, Draw, note editing (`noteedit.js`), mixer strip, stem, MIDI track, MusicXML part and DAWproject note track; a layer (TRACK.1) can be transcribed into a new line.
  - **Acceptance:** Node tests for the field's cleaning and every export; e2e tests that a line is added, edited, undone and exported.
- [ ] **CHAT.2** Hum into the chat: "add a guitar line that goes like this"
  - **Depends:** CHAT.1, AI.2, AI.7
  - A record button in the chat records a hum after the typed request (count-in at the tempo, the take path of REC.2/REC.3 so it lines up with the song). It is transcribed on the device and quantized to the song's grid; the request goes with the hummed notes' summary (length in bars, range, key fit, where the playhead or marked section is) and the new allowlisted action `add_line {instrument, at}` places them: `at` is the marked section, a named section (SONG.1), a bar, or where the hum was sung over the song. One edit, undoable; the line is then edited like any other (CHAT.1), and the chat can be asked to change it (transpose, octave, instrument) with the existing action style. Melody lock is unchanged: a line is not the melody. Needs the "no AI action edits it" decisions amended in `docs/DECISIONS.md` for the new action.
  - **Acceptance:** API tests with a mocked provider for `add_line`'s allowlist and clamping; an e2e test with the fake microphone and a mocked chat reply adds a line at the marked section, undoes it and edits it; chat-eval cases.
- [ ] **CHAT.3** Say it instead of typing it
  - **Depends:** CHAT.2, SPEECH.1

## History of decisions and fixes (2026-11-08 to 2026-11-09)
- Initial idea came from Akai MPC openness, but **no MPC hardware is needed** for Tandem.
- A basic sampler was rejected because the user already has Koala; the target became an interactive music collaborator.
- Named **Tandem**; user requested **full-stack**, not only a prototype.
- GitHub repository: `ogoldberg/tandem-music`; hosted on Vercel instead of split GitHub Pages/Render.
- Provider/model neutrality was explicitly required; text LLM adapters and capability metadata added.
- User requested automated tests; Python and Node workflows added (passing state must be verified).
- Security 503 initially blocked non-paid audio routes; fixed so only `/api/chat` requires an AI token on Vercel.
- Basic Pitch transcription failed at 48 kHz; explicit 22.05 kHz resampling added.
- Initial “polish” was just EQ/dynamics; users wanted **actual pitch correction**.
- Added an experimental proprietary-free pitch shifter, then replaced the active path with WORLD/PyWorld for formant-aware resynthesis.
- Original PyWorld distribution failed in Vercel Python 3.12; switched to a prebuilt wheel and observed a READY deployment. The new audio path still requires quality testing.
- Added simple detected vocal target note +/- controls; VOX.3 replaced them with a visual pitch-contour editor.

## Decisions still open
Default model for conversation (AI.5) and provider choice for generation; license audits for distribution; audio quality targets and sample library; monetization/hosting tier; whether Tandem will be distributed commercially, which decides the model weights it may ship (LIC.1). Decided in ADR-012: a native Mac app with its own local backend comes next, and a DAW plugin or a C++ audio engine such as Tracktion Engine is not planned. The account model, cloud storage and offline strategy were decided in ADR-011 (local-first, no accounts, the user's own storage and keys).
