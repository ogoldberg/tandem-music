# Testing and release-quality checklist

Last reviewed: 2026-11-10. **Test files exist; passing CI status and real-device outcomes are not assumed.**

## Automated suites

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
node --test tests/transcription.test.mjs tests/polish.test.mjs tests/tuning.test.mjs tests/history.test.mjs tests/versions.test.mjs tests/contour.test.mjs tests/groove.test.mjs tests/voices.test.mjs tests/harmony.test.mjs tests/phrases.test.mjs tests/storage.test.mjs tests/recordings.test.mjs tests/samples.test.mjs tests/ideas.test.mjs tests/bundle.test.mjs tests/daw.test.mjs tests/notation.test.mjs tests/dawproject.test.mjs

python -m pip install -r requirements-e2e.txt
python -m playwright install chromium
python -m pytest e2e -q
```
GitHub Actions workflow: `.github/workflows/tests.yml` triggers all three suites (`backend`, `transcription`, `e2e`) on pushes to `main` and pull requests. Inspect https://github.com/ogoldberg/tandem-music/actions for actual run state. The Vercel build status READY means packaging succeeded, **not** that all tests passed.

Python tests cover API health/config, token access, musical action validation, bad-model responses, provider adapter mocks, audio WAV validation, sine/silence transcription, pitch correction routines, WORLD pitch-target/quantization logic (including VOX.3's note shift, Keep vibrato, the stray-frame cap, the `vibrato`/`scale` parameters of `/api/tune`, and a check that the server still matches the shared preview fixture), the VOX.1 pitch-correction benchmark (`tests/test_vocal_benchmark.py`; thresholds and metrics in [AUDIO.md](AUDIO.md#pitch-correction-benchmark-vox1)) and WORLD timing (a tuned clip keeps its length, level and note positions throughout). Node tests cover named versions (`tests/versions.test.mjs`: save/list/restore/delete, reload persistence, name and project validation, the 50-version cap, a full quota, unreadable storage, and unrecognised entries kept through save and delete without counting towards the cap), Basic Pitch event conversion and its project-melody vs vocal-target limits (with an injected Basic Pitch module), 48,000 → 22,050 Hz resampling using a mocked OfflineAudioContext, and chunked tuning (`tests/tuning.test.mjs`: chunk plan within the request caps, note targets offset to each chunk, exact reconstruction, no clicks or level gaps at seams, 429 retry), on-device polish (`tests/polish.test.mjs`: parity with the original SciPy output at 16 and 44.1 kHz, filter response, a 5-minute recording, input validation), the pitch-contour editor model (`tests/contour.test.mjs`: Basic Pitch frame timing and contour pitch, note centres, scales, snapping and scale-degree steps, fragment merging, edge resizing, and the correction preview against the server's output on `tests/fixtures/target-correction.json`), and the edit history (`tests/history.test.mjs`: undo/redo order and labels, redo cleared by a new edit, no-op edits skipped, the size cap, and `rewrite` dropping edits that became no-ops).

Browser end-to-end tests (`e2e/`, CI.2) start the real app with uvicorn and drive headless Chromium through Playwright: load `/`, import a 48 kHz WAV of three tones, transcribe with the server fallback (`/api/analyze`, expecting MIDI 69/72/76), remove a note and undo, add a note and a drum hit, play and stop, export WAV (checked non-silent), MIDI and project JSON, clear and reopen the saved project, and reload to restore the localStorage draft. A second test (EDIT.1) walks one history through Load example, removing a note, instrument and tempo changes, an AI chat reply (the real chat form and action applier, with only the `/api/chat` response fulfilled by the test because CI has no provider credentials), and Open project; it undoes and redoes all of them with the buttons, Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z and Ctrl+Y, checks that Ctrl+Z in a text field is left alone, that a new edit clears redo and a no-op edit is not recorded, then detects sung notes with on-device Basic Pitch, undoes/redoes a vocal target arrow-key step, and checks that a new recording drops the old targets from history. A third test (PERF.3) imports a 3-minute WAV of held sung-range tones and runs real on-device Basic Pitch through Detect sung notes, expecting more than 128 targets, targets past 170 s and over 100 after 60 s; it takes about 2 minutes. The fixtures launch Chromium with `--enable-unsafe-swiftshader` so GPU-less machines such as GitHub runners still get software WebGL; without it TensorFlow.js falls back to its CPU backend and the test times out at "Detecting vocal notes…". A VOX.3 test detects the three tones on device and checks one target per tone at the sung pitch, each with a confidence, then drags a target up two semitones, drags another's end edge, steps a target with the arrow keys, picks C major and snaps (the A♯/B tie goes to the sung A), steps by scale degree, deletes and undoes, and confirms the `/api/tune` request carries exactly the edited `m`/`t`/`d` targets (no confidence) and the Keep vibrato amount before tuning completes. It then deletes every target and checks that Tune is disabled with a message pointing to Undo / Reset note edits, and that Undo, Redo and Reset note edits switch Tune back on and off (issue #23). A fourth test (EDIT.2) saves two named versions, rejects a blank name, restores one (checking notes, drums and tempo) and undoes the restore, reloads to confirm versions persist, and deletes one; another restores a hand-edited version without tempo or instrument and gets 100 bpm and piano. A test fails on any uncaught page error or `console.error`. A TRANS.1 test imports a hummed melody (`hum_wav`: six 1.4 s notes with vibrato, drift and room noise) and transcribes it with on-device Basic Pitch, expecting exactly the six hummed pitches as six notes (the model alone gives 60 or more pieces); `tests/contour.test.mjs` and `tests/transcription.test.mjs` cover the merge with a wide-vibrato split, a short dropout of the sung line versus a breath, and the melody path. They do not cover Basic Pitch transcription of real hums, microphone recording, polish, the sound of tuned audio, or AI chat against a real model, and headless Chromium is not a substitute for the real-device matrix below. When the CI e2e job fails it uploads two artifacts: `e2e-traces` (Playwright traces) and `e2e-server-log` (the uvicorn log). Locally the log goes to a pytest temporary directory; set `E2E_SERVER_LOG=<path>` to keep it somewhere known. `python -m pytest` without a path runs only `tests/` (see `pytest.ini`).

Waits in e2e tests (CI.3): never pass an async function to `page.wait_for_function`. Its Promise is truthy, so the wait returns at once; poll inside the page instead with `wait_until` in `e2e/test_studio.py`. Do not wait for a status text that may only show for a moment: record the texts with a `MutationObserver` and check them afterwards. Lengthen a timeout only where the CI log shows the work finishing late, not hanging.

## Audio test requirements
Generate controlled dry solo singing samples with known MIDI pitches/timing, multiple sample rates and realistic consonants, vibrato and noise; preserve consent and privacy. Test 0% strength equivalence, clipping, silence, note overlaps and transitions. Measure pitch error, duration, loudness, artifacts and listener preference. Verify quality against real human vocals—synthetic sines alone are insufficient.
