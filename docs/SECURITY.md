# Security, privacy and cost controls

Last reviewed: 2026-11-10. Tandem is an **experimental public web app**, not a production-ready multi-user service.

## Current boundaries
- GitHub repository is public. Outsiders can read/fork/propose PRs; they cannot push without permissions. **Branch-protection status has not been verified**. Configure rulesets: required PR review, tests, no force pushes, restrict bypass.
- Vercel hosts frontend and backend. Production `/api/chat` refuses calls without configured `TANDEM_ACCESS_TOKEN`; with one, callers supply it as `x-tandem-token`. This is a shared bearer secret, **not user authentication**.
- `TANDEM_API_KEY` belongs exclusively in Vercel server variables. Never put provider keys in JS, project JSON, README, Git history, issue reports or chat.
- `/api/analyze` and `/api/tune` are public and consume CPU. They are rate-limited per client IP through a shared Upstash Redis store and their inputs are bounded (see **Request limits** below). Per-IP limits do not stop a distributed attacker; abuse can still incur infrastructure cost.
- The browser saves the project draft and named versions in IndexedDB, and the recordings (original, polished and tuned audio) as files in the Origin Private File System (STORE.2a; older versions used `localStorage`, which is migrated and cleared on start). Recordings never leave the device unless the user sends one for server analysis or pitch correction. Anyone using the same browser profile can read them; avoid shared devices and clear site data after using them.
- **Access token storage (AI.3).** After a successful **Test connection**, the access token is kept in `sessionStorage` under `tandem-token`: it survives a reload of that tab and is gone when the tab closes; other tabs do not see it, though browsers copy it into a tab duplicated from this one, and a browser restoring a previous session may restore it too. It is never written to `localStorage`, and on load the app deletes the `tandem-token` key older versions left there. Connecting with an empty field forgets it. While the tab is open the token is still readable by script on the page (any XSS could take it), and it is still a shared secret, not per-user authentication. We chose this over an HttpOnly session cookie because a cookie needs a server-side signing secret and session handling for little gain while there is one shared token; revisit it with real accounts.
- The application does not implement server-side project storage. Vocal polish runs in the browser, so that audio is never uploaded. Audio sent for server analysis or tuning is read into memory for a request; do not assume zero logs, network metadata or cloud retention outside our code.
- **Tandem files (MOB.3).** A shared `.tandem.zip` is untrusted input read entirely in the browser; nothing is uploaded. `bundle.js` refuses encrypted, damaged (CRC or size mismatch) and ZIP64 entries and more than 512 MB of content, checking declared sizes before inflating and stopping a deflate stream that grows past its declared size; the project inside goes through the same checks as Open project before anything changes, and recordings must be WAV. Sharing hands the file to the operating system's share sheet; where it goes from there (AirDrop, iCloud Drive) is the user's choice.
- The app icons (MOB.2) are served by `/icons/{name}` only for the four PNG names in `ICON_FILES`; anything else, including the SVG sources, is a 404.
- The General MIDI instrument samples (SND.1) are self-hosted the same way: the browser loads them only from this app, at `/vendor/gm-samples-1/`, with no CDN. `tools/gm-samples/build.py` renders them from FluidR3_GM.sf2 (Frank Wen, MIT license), taken from Debian's `fluid-soundfont-gm_3.1-6_all.deb`, whose SHA-256 the script checks before use. The output SHA-256 hashes are committed in `vendor/gm-samples-1/SHA256SUMS`; `tests/test_api.py` checks that the served bytes match them, and `python tools/gm-samples/build.py --check` checks that a fresh build reproduces them. The route serves only files listed in `SHA256SUMS` (not `SHA256SUMS` itself), as immutable. The license is recorded in `vendor/gm-samples-1/LICENSES.txt` (the Debian copyright file). A changed sample set must move to a new versioned directory.
- On-device Basic Pitch is self-hosted (SEC.3): the browser loads its JS bundle and model only from this app, at `/vendor/basic-pitch-1.0.1/`, with no CDN. `tools/basic-pitch/build.sh` rebuilds them from npm with `npm ci`, which checks every package tarball against the sha512 in `tools/basic-pitch/package-lock.json` (Basic Pitch 1.0.1, TensorFlow.js 3.21.0 pinned exactly; the old esm.sh URL resolved TensorFlow.js `^3.2.0` at request time). The output SHA-256 hashes are committed in `vendor/basic-pitch-1.0.1/SHA256SUMS`; `tests/test_api.py` checks that the served bytes match them, and `bash tools/basic-pitch/build.sh --check` checks that a fresh build reproduces the committed files byte for byte. The route serves only those three files. Bundled package licenses, with the license or notice text for each package, are in `vendor/basic-pitch-1.0.1/LICENSES.txt`; the build fails if a bundled package's license text cannot be found. To upgrade, change the versions in `tools/basic-pitch/package.json` and regenerate the lockfile, then change the versioned directory name everywhere it is hard-coded (`dest` in `tools/basic-pitch/build.sh`, the vendor route and `/api/config` model name in `tandem_backend.py`, the URLs in `transcription.js` and the vendor tests in `tests/test_api.py`), run the build, delete the old directory and review the diff of `SHA256SUMS`. A new directory name keeps browsers from mixing cached old and new files (the route serves them as immutable).
- **Mac app (DESK.1).** `python -m tandem_desktop` runs the same app on a listening socket bound to `127.0.0.1` only, never to other interfaces. Every HTTP request must carry exactly `Host: 127.0.0.1:<port>`; any other host, a missing one or a second one gets `421 Unknown host` (and a WebSocket is closed), which stops DNS-rebinding pages in the user's browser from reading the local server through a host name of their own. A page in the user's browser can still send requests to `http://127.0.0.1:<port>` itself, with the right Host; DESK.2 closes that. Each launch makes a new secret (`secrets.token_urlsafe(32)`, kept only in the launcher's memory) and gives it to its own window's page through a WebKit user script that defines it only when the page's origin is `http://127.0.0.1:<port>`. Every `/api/` request must carry it in the `x-tandem-launch` header (compared in constant time; not read from a query string or a cookie, and never passed on a command line, so it does not reach logs, shell history or the process list); without it the answer is 403 before any route runs. Any request with an `Origin` other than `http://127.0.0.1:<port>` gets 403 before CORS runs, so no other origin, including the hosted list's `https://ogoldberg.github.io`, gets CORS approval or reaches a route, even with a simple request that needs no preflight. The page and its static files load without the secret (they hold nothing private, and the window needs them to start). Only requests that passed these checks get the Mac app's lifted limits (no rate limit, 10 minutes per audio request, see below). **Threat model:** the secret keeps out web pages in the user's browser, including through DNS rebinding; it does not keep out other programs running as the same user, which can read the launcher's memory or the web view and could reach the local server anyway; those are outside this threat model. **Project folders (DESK.3).** The Mac app's server writes and reads files on disk only through `/api/desktop/project/save` and `/api/desktop/project/open`, which exist only behind `guarded_app` (so they need the launch secret, the app's own origin and Host) and are absent from the hosted app. The page never names a path: each request opens a native dialog and the folder is the one the person picks there. Only `project.json`, `tandem.json`, `original.wav`, `polished.wav` and `tuned.wav` are written or read; a zip with any other entry (including `../` or folder paths) is refused, each recording must be a WAV and the project a Tandem project, and bodies and folders are capped at 512 MB. A save into an existing folder that holds other files is refused unless its `project.json` is a Tandem project (another tool's `project.json`, such as Nx's, does not count), so a project is never mixed into someone else's folder; other files in a project folder are left alone. The window's web view grants the microphone without a prompt only to `http://127.0.0.1:<port>` (scheme, host and port all checked, `tandem_desktop.allow_media`) and denies the camera and microphone-with-camera requests; on macOS a camera request does not reach that rule at all, because macOS first asks for camera access for the whole process (the studio never asks for the camera). Running from source, macOS's own microphone permission belongs to the app that started Python. The web view's storage is persistent (`private_mode=False`), but `navigator.storage.persist()` returns false in WKWebView, so whether WebKit can evict it under storage pressure is not established; export projects you care about.
- The backend validates LLM edit actions and the `/api/chat` request schema; `/api/chat` itself is not rate-limited beyond the shared token. Threat modeling and audit logs are still missing.

## Request limits (SEC.1)
Enforced by `RequestGuardMiddleware` in `request_guards.py` before a route reads its body. These are the hosted limits; in the Mac app, requests from its own window (checked by `tandem_desktop.guarded_app`, DESK.2) are not rate-limited and may send up to 240,000,000 bytes and 600 s of audio (`/api/tune` up to 600 s and 4096 note targets) in one request:

| Limit | Value | Applies to | Response |
|---|---|---|---|
| Rate limit, one shared bucket per client IP (IPv6 clients per /64) | 20 requests per 60 s fixed window (`TANDEM_AUDIO_RATE_LIMIT`, `TANDEM_AUDIO_RATE_WINDOW_SECONDS`) | `POST /api/analyze`, `/api/tune` | 429 with `Retry-After` |
| Request body | 18,000,000 bytes (checked on `Content-Length` and while streaming) | audio routes | 413 |
| Request body | 262,144 bytes | `POST /api/chat` | 413 |
| WAV format | 16-bit PCM, 1-2 channels, 8-96 kHz, 1 frame to 90 s; anything else or unparseable | audio routes | 400 |
| Tune clip length | 25 s per request (the browser sends long recordings as 16 s chunks) | `/api/tune` | 400 |
| Chat project | typed: `bpm` 45-220, `instrument` one of piano/marimba/strings/bass/chip/organ/guitar/flute (the `INSTRUMENTS` tuple), at most 1024 `notes` (`m` 0-127, `t` 0-600 s, `d` >0-600 s) and 1024 `drums` (`k` kick/snare/hat), boolean `melody_locked`, optional `harmony` (at most 1024 notes, same rules as `notes`) and `harmony_instrument` (one of the instruments), no other keys; `history` at most 12 user/assistant turns of 3000 chars (the message cap, since the browser sends past messages back) | `/api/chat` | 422 |

**Where rate-limit state lives.** Vercel serverless instances do not share memory, so counters live in Upstash Redis (`UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`, or the Vercel KV names `KV_REST_API_URL` + `KV_REST_API_TOKEN`), keyed `tandem:rl:audio:<client-ip>:<window>` and expiring after the window. On Vercel the client IP comes from `x-forwarded-for`, which the platform overwrites with the real address; elsewhere the socket address is used. **On Vercel without a configured store, or when the store errors, audio routes fail closed with 503** rather than run unlimited. Outside Vercel (local development, one process) an in-process counter is used when no store is configured.

Vercel's own platform limit on a function request body is 4.5 MB (per Vercel's documentation; not yet measured against this app), below the app's 18 MB cap, so long uncompressed WAVs (about 50 s of 44.1 kHz mono) are refused in production before they reach the app.

## Bring your own keys and storage (ADR-011)
**In the Mac app (AI.4, implemented; real-provider QA pending):** the person's AI key is kept in the macOS Keychain, as a generic password with the service `Tandem AI key` and the provider id (`openai`, `anthropic`, `gemini`, `openrouter`) as the account, or for another OpenAI-compatible server `custom <address>` (the address with its scheme and host lowercased and no trailing slash), so a key saved for one server is never sent to another: changing the address finds no key there, and saving the new address removes the old address's key, written and read through `keyring` by the local server (`tandem_desktop/ai_keys.py`). The provider and model (and, for another OpenAI-compatible server, its address) are kept in `ai.json` in the Mac app's settings folder (`~/Library/Application Support/Tandem/`); the key never is. The page sends the key once, to `PUT /api/desktop/ai` on its own server, which exists only behind `guarded_app` (the launch secret, the app's own origin and host) and never on the hosted app. No answer gives the key back: the page is told only whether one is saved (`has_key`), the answers are `Cache-Control: no-store`, and a Keychain failure is reported by its error type only. The key is sent only to the provider chosen, in that provider's header (`Authorization: Bearer`, `x-api-key` or `x-goog-api-key`), by the existing `invoke_llm`, and a failed provider call reports the status and URL, not the headers. It is never written to a project, a Tandem file, a project folder or a log. **Remove key** deletes the Keychain item. A model reply goes through the same `normalize_actions` and melody lock as the hosted mode. Saved settings apply only to requests `guarded_app` marked local; the hosted app ignores them. Anyone who can read the person's login Keychain (their macOS account) can read the key; macOS may ask to allow access when Python or the app changes.

**Model downloads in the Mac app (MODEL.1):** model files are downloaded only when the person asks, from the https URL pinned in `tandem_desktop/models.py`'s catalog, and kept only when their size and SHA-256 match the pin; a file that does not match is deleted and nothing is installed. Every file is hashed again before a model loads, so a file changed on disk is refused. The download and job routes exist only behind `guarded_app` (the launch secret, the app's own origin and host); the hosted app never imports the module. Model files are code-adjacent (a PyTorch checkpoint can run code when loaded unsafely), which is why the pin is a hash and not only a URL; each model that uses the runtime must load its weights without executing pickled code where the library allows it, and its catalog entry records the licence (LIC.1 decides which weights may be distributed).

**Voice separation (SEP.1):** the htdemucs weights are a safetensors file pinned to one commit of `adefossez/HTDemucs` on Hugging Face (URL, SHA-256, size) and checked by MODEL.1 before every load. They are read with safetensors, never with `torch.load`, so loading cannot run pickled code, and `load_htdemucs` accepts only the `demucs.htdemucs.HTDemucs` class from the file's metadata. `/api/desktop/separate` exists only behind `guarded_app` (launch secret, own origin and host), takes a WAV of up to 10 minutes under a 256 MB body cap, runs one separation at a time and keeps the stems of the last two in memory only. (Demucs' former download host, `dl.fbaipublicfiles.com`, served an expired TLS certificate on 2026-11-12; Tandem does not use it.)

**Backing band (GEN.2):** MusicGen-Melody's files are pinned to one commit of `facebook/musicgen-melody` (URL, SHA-256, size each) and checked by MODEL.1 before every load; only the safetensors weights are downloaded, never the repository's pickled `state_dict.bin` files, and transformers loads them with `local_files_only=True`, `use_safetensors=True` and `trust_remote_code=False`. The weights are licensed CC-BY-NC 4.0 (non-commercial use only): the window says so before the download and on every generated band, and LIC.1 must settle it before any distribution. `/api/desktop/band` exists only behind `guarded_app`, takes the style as one line of at most 200 printable characters, the tempo and key only in fixed formats, a WAV of up to 10 minutes under a 128 MB body cap (only the first 30 s is used), runs one generation at a time and keeps the last two bands in memory only.

These are the rules the later optional web-app path of AI.4 and STORE.2c (parked) must meet:
- On the web path, a user's own AI or storage key is kept only in their browser and sent only to the provider they chose, never to the Tandem server. A browser test must prove it.
- Any script running on the page can read a key kept in the browser, so XSS or a malicious extension means key theft. Before any key is stored the app needs a strict Content Security Policy: no inline script that is not hashed (the studio script is inline today), no third-party script, and `connect-src` limited to the app, the providers in use and any backend URL or local Ollama address the user entered. The policy must still allow the page's inline styles (or move them out) and WebAssembly compilation (`wasm-unsafe-eval`) for on-device tuning (VOX.4).
- How long a key is kept follows ADR-009 by default (the tab session); remembering it longer is an explicit user choice with a warning.
- Model replies called from the browser are validated in the browser exactly as `normalize_actions` and melody lock do on the server, and checked against the same fixtures.
- Users should set their own spend limits at their provider. The Tandem spend guards (shared token, Upstash rate limits) protect only the hosted mode.
- Projects and recordings in IndexedDB/OPFS are readable by anyone using that browser profile; the shared-device advice above applies.

## Before enabling paid AI
These apply to the optional hosted mode (operator's key on Vercel), not to bring-your-own keys.

1. Set `TANDEM_ACCESS_TOKEN` to a strong random secret; set provider/model/key only on Vercel.
2. Configure provider budget/caps and alerts. Be aware shared access tokens can be copied or stolen.
3. Avoid logging audio, secrets or complete personal prompts.
4. Add authentication, per-user quotas, safe usage limits and abuse monitoring before public commercial launch.
5. Separate project ownership and persistent object storage if cloud saving is introduced.

## Other safeguards
- Browser microphone access requires permission and HTTPS.
- Short clip, WAV-format and body-size limits are enforced and tested (`tests/test_api.py`); CPU cost of a maximum-size request has not been profiled on Vercel.
- No commercial plugin binaries or copyrighted sample libraries are redistributed.
- Run dependency/license/vulnerability reviews and independent privacy/security testing.
- Report discovered vulnerabilities privately to the repository owner instead of opening public issues with exploit details.
