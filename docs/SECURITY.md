# Security, privacy and cost controls

Last reviewed: 2026-11-17 (whole-repo security audit; see **Audit 2026-11-17** below). Tandem is an **experimental public web app**, not a production-ready multi-user service.

## Current boundaries
- GitHub repository is public. Outsiders can read/fork/propose PRs; they cannot push without permissions. **Branch-protection status has not been verified**. Configure rulesets: required PR review, tests, no force pushes, restrict bypass.
- Vercel hosts frontend and backend. Production `/api/chat` refuses calls without configured `TANDEM_ACCESS_TOKEN`; with one, callers supply it as `x-tandem-token`, compared in constant time. This is a shared bearer secret, **not user authentication**: make it long and random (`python -c 'import secrets; print(secrets.token_urlsafe(32))'`). Chat is rate-limited per client (see **Request limits**), so a leaked token cannot spend without limit; set a spend cap at the provider as well. A chat request sends the whole project (notes, rhythms, lyrics, song sections, genre, mixer settings, the band's description and the names of takes and layers; never audio) and the last 10 chat turns to the AI provider, and, while a practice pass is marked on the melody, that pass's per-note scores (PRACTICE.4).
- `TANDEM_API_KEY` belongs exclusively in Vercel server variables. Never put provider keys in JS, project JSON, README, Git history, issue reports or chat.
- `/api/analyze` and `/api/tune` are public and consume CPU. They are rate-limited per client IP through a shared Upstash Redis store and their inputs are bounded (see **Request limits** below). Per-IP limits do not stop a distributed attacker; abuse can still incur infrastructure cost.
- The browser saves the project draft and named versions in IndexedDB, and the recordings (original, polished and tuned audio) as files in the Origin Private File System (STORE.2a; older versions used `localStorage`, which is migrated and cleared on start). PRACTICE.2 keeps the singer's range and per-stretch practice scores in the same IndexedDB (key `practice`), never sent anywhere; Forget range and progress clears them. Recordings never leave the device unless the user sends one for server analysis or pitch correction. Anyone using the same browser profile can read them; avoid shared devices and clear site data after using them.
- **Access token storage (AI.3).** After a successful **Test connection**, the access token is kept in `sessionStorage` under `tandem-token`: it survives a reload of that tab and is gone when the tab closes; other tabs do not see it, though browsers copy it into a tab duplicated from this one, and a browser restoring a previous session may restore it too. It is never written to `localStorage`, and on load the app deletes the `tandem-token` key older versions left there. Connecting with an empty field forgets it. While the tab is open the token is still readable by script on the page (any XSS could take it), and it is still a shared secret, not per-user authentication. We chose this over an HttpOnly session cookie because a cookie needs a server-side signing secret and session handling for little gain while there is one shared token; revisit it with real accounts.
- The application does not implement server-side project storage. Vocal polish runs in the browser, so that audio is never uploaded. Audio sent for server analysis or tuning is read into memory for a request; do not assume zero logs, network metadata or cloud retention outside our code.
- **Tandem files (MOB.3).** A shared `.tandem.zip` is untrusted input read entirely in the browser; nothing is uploaded. `bundle.js` refuses encrypted, damaged (CRC or size mismatch) and ZIP64 entries and more than 512 MB of content, checking declared sizes before inflating and stopping a deflate stream that grows past its declared size; the project inside goes through the same checks as Open project before anything changes, and recordings must be WAV. Sharing hands the file to the operating system's share sheet; where it goes from there (AirDrop, iCloud Drive) is the user's choice.
- The app icons (MOB.2) are served by `/icons/{name}` only for the four PNG names in `ICON_FILES`; anything else, including the SVG sources, is a 404.
- The General MIDI instrument samples (SND.1) are self-hosted the same way: the browser loads them only from this app, at `/vendor/gm-samples-1/`, with no CDN. `tools/gm-samples/build.py` renders them from FluidR3_GM.sf2 (Frank Wen, MIT license), taken from Debian's `fluid-soundfont-gm_3.1-6_all.deb`, whose SHA-256 the script checks before use. The output SHA-256 hashes are committed in `vendor/gm-samples-1/SHA256SUMS`; `tests/test_api.py` checks that the served bytes match them, and `python tools/gm-samples/build.py --check` checks that a fresh build reproduces them. The route serves only files listed in `SHA256SUMS` (not `SHA256SUMS` itself), as immutable. The license is recorded in `vendor/gm-samples-1/LICENSES.txt` (the Debian copyright file). A changed sample set must move to a new versioned directory.
- On-device Basic Pitch is self-hosted (SEC.3): the browser loads its JS bundle and model only from this app, at `/vendor/basic-pitch-1.0.1-2/`, with no CDN. `tools/basic-pitch/build.sh` rebuilds them from npm with `npm ci`, which checks every package tarball against the sha512 in `tools/basic-pitch/package-lock.json` (Basic Pitch 1.0.1, TensorFlow.js 3.21.0 pinned exactly; the old esm.sh URL resolved TensorFlow.js `^3.2.0` at request time). The output SHA-256 hashes are committed in `vendor/basic-pitch-1.0.1-2/SHA256SUMS`; `tests/test_api.py` checks that the served bytes match them, and `bash tools/basic-pitch/build.sh --check` checks that a fresh build reproduces the committed files byte for byte. The route serves only those three files. Bundled package licenses, with the license or notice text for each package, are in `vendor/basic-pitch-1.0.1-2/LICENSES.txt`; the build fails if a bundled package's license text cannot be found. To upgrade, change the versions in `tools/basic-pitch/package.json` and regenerate the lockfile, then change the versioned directory name everywhere it is hard-coded (`dest` in `tools/basic-pitch/build.sh`, the vendor route and `/api/config` model name in `tandem_backend.py`, the URLs in `transcription.js` and the vendor tests in `tests/test_api.py`), run the build, delete the old directory and review the diff of `SHA256SUMS`. A new directory name keeps browsers from mixing cached old and new files (the route serves them as immutable).
- **Mac app (DESK.1).** `python -m tandem_desktop` runs the same app on a listening socket bound to `127.0.0.1` only, never to other interfaces. Every HTTP request must carry exactly `Host: 127.0.0.1:<port>`; any other host, a missing one or a second one gets `421 Unknown host` (and a WebSocket is closed), which stops DNS-rebinding pages in the user's browser from reading the local server through a host name of their own. A page in the user's browser can still send requests to `http://127.0.0.1:<port>` itself, with the right Host; DESK.2 closes that. Each launch makes a new secret (`secrets.token_urlsafe(32)`, kept only in the launcher's memory) and gives it to its own window's page through a WebKit user script that defines it only when the page's origin is `http://127.0.0.1:<port>`. Every `/api/` request must carry it in the `x-tandem-launch` header (compared in constant time; not read from a query string or a cookie, and never passed on a command line, so it does not reach logs, shell history or the process list); without it the answer is 403 before any route runs. Any request with an `Origin` other than `http://127.0.0.1:<port>` gets 403 before CORS runs, so no other origin, including the hosted list's `https://ogoldberg.github.io`, gets CORS approval or reaches a route, even with a simple request that needs no preflight. The page and its static files load without the secret (they hold nothing private, and the window needs them to start). Only requests that passed these checks get the Mac app's lifted limits (no rate limit, 10 minutes per audio request, see below). **Threat model:** the secret keeps out web pages in the user's browser, including through DNS rebinding; it does not keep out other programs running as the same user, which can read the launcher's memory or the web view and could reach the local server anyway; those are outside this threat model. **Project folders (DESK.3).** The Mac app's server writes and reads files on disk only through `/api/desktop/project/save` and `/api/desktop/project/open`, which exist only behind `guarded_app` (so they need the launch secret, the app's own origin and Host) and are absent from the hosted app. The page never names a path: each request opens a native dialog and the folder is the one the person picks there. Only `project.json`, `tandem.json`, `original.wav`, `polished.wav` and `tuned.wav` are written or read; a zip with any other entry (including `../` or folder paths) is refused, each recording must be a WAV and the project a Tandem project (a polished or tuned recording without the original is refused), and bodies and folders are capped at 512 MB. A folder's files are read only as plain files in it: each is opened with `O_NOFOLLOW` (and `O_NONBLOCK`) and checked as a regular file on the open descriptor, so a link, including one swapped in while the folder is being read, a FIFO or a folder is refused, never followed. A save into an existing folder that holds other files is refused unless its `project.json` is a Tandem project (another tool's `project.json`, such as Nx's, does not count), so a project is never mixed into someone else's folder; other files in a project folder are left alone. The window's web view grants the microphone without a prompt only to `http://127.0.0.1:<port>` (scheme, host and port all checked, `tandem_desktop.allow_media`) and denies the camera and microphone-with-camera requests; on macOS a camera request does not reach that rule at all, because macOS first asks for camera access for the whole process (the studio never asks for the camera). Running from source, macOS's own microphone permission belongs to the app that started Python. The web view's storage is persistent (`private_mode=False`), but `navigator.storage.persist()` returns false in WKWebView, so whether WebKit can evict it under storage pressure is not established; export projects you care about.
- The backend validates LLM edit actions and the `/api/chat` request schema, and rate-limits `/api/chat` per client after the token check. Threat modeling and audit logs are still missing.

## Audit 2026-11-17
A whole-repo static audit (seven dimensions: crypto, authorization and sessions, secrets and storage, input and injection, silent failure, dependencies and supply chain, privacy invariants; every finding verified adversarially) found no critical issues. Fixed:
- **High: stored DOM XSS through a recorded layer's name.** A shared project or Tandem file could name a layer so that it closed the mixer strip's `aria-label` in `innerHTML` and added an element with an event handler. The labels are now set with `setAttribute`; `e2e/test_injection.py` opens such a project and checks nothing is injected. No other `innerHTML` takes user text.
- **Low:** `/api/chat` rate-limited per client; a key never sent over `http://` to another machine from the Mac app; dependency floors raised past known multipart/Range DoS releases (`python-multipart>=0.0.18`, `starlette>=0.49.1`); the access token compared in constant time; a provider error no longer echoes the provider URL; CI runs with a read-only token; the chat disclosure says chat sends the whole project and the recent chat.

Fixed since (SEC.6): with "This device" chosen a beat take is read on the device by `beatbox.js` and never sent to `/api/analyze` (the guided flow's automatic Transcribe, rhythm-mode Transcribe and a layer transcribed into the drums; `e2e/test_beatbox.py`).

Fixed since (SEC.8): off Vercel too, `/api/chat` without a token and the in-process rate-limit store are only for a request from this computer, unless the operator says otherwise in the env (see **Self-hosting off Vercel (SEC.8)** below).

Fixed since (SEC.9): every install reads a hashed lock compiled from the `requirements*.in` sources (`tools/locks/compile.sh`; Vercel installs `requirements.txt`), which pip and uv check file by file; CI's `audit` job runs pip-audit over every lock and fails on a known vulnerability (this moved the tests to pytest 9 with pytest-playwright 0.10, past PYSEC-2026-1845); every CI action is pinned to a commit SHA; a RAVE TorchScript model is loaded from the bytes whose SHA-256 was checked (`ModelStore.read_verified`), never by reopening the file; in the Mac app, Tune's server engine always posts to the app's own server, whatever API base was saved. The separation CI job still installs from the `.in` sources, since the models lock is for Apple silicon. Every finding from the audit is now fixed.

## Request limits (SEC.1)
Enforced by `RequestGuardMiddleware` in `request_guards.py` before a route reads its body. These are the hosted limits; in the Mac app, requests from its own window (checked by `tandem_desktop.guarded_app`, DESK.2) are not rate-limited and may send up to 240,000,000 bytes and 600 s of audio (`/api/tune` up to 600 s and 4096 note targets) in one request:

| Limit | Value | Applies to | Response |
|---|---|---|---|
| Rate limit, one shared bucket per client IP (IPv6 clients per /64) | 20 requests per 60 s fixed window (`TANDEM_AUDIO_RATE_LIMIT`, `TANDEM_AUDIO_RATE_WINDOW_SECONDS`) | `POST /api/analyze`, `/api/tune` | 429 with `Retry-After` |
| Rate limit, a separate bucket per client IP, counted only after the token check (a wrong token is a 401 and costs nothing) | 10 requests per 60 s fixed window (`TANDEM_CHAT_RATE_LIMIT`, `TANDEM_CHAT_RATE_WINDOW_SECONDS`); not in the Mac app's own window | `POST /api/chat` | 429 with `Retry-After` |
| Request body | 18,000,000 bytes (checked on `Content-Length` and while streaming) | audio routes | 413 |
| Request body | 262,144 bytes | `POST /api/chat` | 413 |
| WAV format | 16-bit PCM, 1-2 channels, 8-96 kHz, 1 frame to 90 s; anything else or unparseable | audio routes | 400 |
| Tune clip length | 25 s per request (the browser sends long recordings as 16 s chunks) | `/api/tune` | 400 |
| Chat project | typed: `bpm` 45-220, `instrument` one of piano/marimba/strings/bass/chip/organ/guitar/flute (the `INSTRUMENTS` tuple), at most 1024 `notes` (`m` 0-127, `t` 0-600 s, `d` >0-600 s) and 1024 `drums` (`k` kick/snare/hat), boolean `melody_locked`, optional `harmony` (at most 1024 notes, same rules as `notes`) and `harmony_instrument` (one of the instruments), optional `voice2` (the harmony voice, HARM.1: at most 1024 notes, same rules) and `voice2_instrument`, no other keys; `history` at most 12 user/assistant turns of 3000 chars (the message cap, since the browser sends past messages back) | `/api/chat` | 422 |

**Where rate-limit state lives.** Vercel serverless instances do not share memory, so counters live in Upstash Redis (`UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`, or the Vercel KV names `KV_REST_API_URL` + `KV_REST_API_TOKEN`), keyed `tandem:rl:audio:<client-ip>:<window>` (chat: `tandem:rl:chat:...`) and expiring after the window. On Vercel the client IP comes from `x-forwarded-for`, which the platform overwrites with the real address; elsewhere the socket address is used. **On Vercel without a configured store, or when the store errors, audio routes and chat fail closed with 503** rather than run unlimited. Outside Vercel with no store configured, an in-process counter is used only for a request from this computer or when `TANDEM_RATE_LIMIT_STORE=memory` is set; any other request to a limited route gets 503 (SEC.8).

## Self-hosting off Vercel (SEC.8)
What a server off Vercel allows is decided from what is configured and where the request comes from, not from the host:
- **From this computer** (`request_guards.from_this_computer`) means the Mac app's own window (DESK.2), or a loopback socket whose `X-Forwarded-For`, `X-Real-IP` and `Forwarded: for=` headers, if any, name only loopback addresses (an IPv4-mapped `::ffff:127.0.0.1` counts, as portless sends it for an IPv4 browser). So local development, also through a local proxy such as portless, works as before; a proxy on this computer forwarding another machine names that machine and is not this computer.
- **Chat** without `TANDEM_ACCESS_TOKEN` answers only requests from this computer; anyone else gets 503. `TANDEM_ALLOW_OPEN_CHAT=1` (or `true`, `yes`) opens it to everyone off Vercel (the operator's choice, e.g. a private network). `/api/config` tells a client that chat would refuse that AI is not ready, with the reason in `ai_problem`, which the studio's Connect shows. On Vercel a token is always required; `TANDEM_ALLOW_OPEN_CHAT` is ignored there.
- **Rate limits** use Upstash when it is configured. Without it, the in-process counter serves requests from this computer, and serves everyone only with `TANDEM_RATE_LIMIT_STORE=memory`, which is right only for one process that sees each client's own address (not behind a proxy, where every client shares the proxy's bucket). Otherwise `/api/analyze`, `/api/tune` and `/api/chat` return 503 naming `TANDEM_RATE_LIMIT_STORE`. A phone on the same network using a development server's audio routes therefore needs `TANDEM_RATE_LIMIT_STORE=memory`.
- **Behind a proxy that sends no forwarding header**, every request arrives from loopback and looks like this computer. Self-hosting behind such a proxy must set `TANDEM_ACCESS_TOKEN` and an Upstash store (or make the proxy send `X-Forwarded-For`).

Vercel's own platform limit on a function request body is 4.5 MB (per Vercel's documentation; not yet measured against this app), below the app's 18 MB cap, so long uncompressed WAVs (about 50 s of 44.1 kHz mono) are refused in production before they reach the app.

## Bring your own keys and storage (ADR-011)
**In the Mac app (AI.4, implemented; real-provider QA pending):** the person's AI key is kept in the macOS Keychain, as a generic password with the service `Tandem AI key` and the provider id (`openai`, `anthropic`, `gemini`, `openrouter`) as the account, or for another OpenAI-compatible server `custom <address>` (the address with its scheme and host lowercased and no trailing slash), so a key saved for one server is never sent to another: changing the address finds no key there, and saving the new address removes the old address's key, written and read through `keyring` by the local server (`tandem_desktop/ai_keys.py`). The provider and model (and, for another OpenAI-compatible server, its address) are kept in `ai.json` in the Mac app's settings folder (`~/Library/Application Support/Tandem/`); the key never is. The page sends the key once, to `PUT /api/desktop/ai` on its own server, which exists only behind `guarded_app` (the launch secret, the app's own origin and host) and never on the hosted app. No answer gives the key back: the page is told only whether one is saved (`has_key`), the answers are `Cache-Control: no-store`, and a Keychain failure is reported by its error type only. The key is sent only to the provider chosen, in that provider's header (`Authorization: Bearer`, `x-api-key` or `x-goog-api-key`), by the existing `invoke_llm`, and a failed provider call reports only the provider's status code (or the error's type), never the URL or headers. A key is never sent over plain `http://` to another machine: for another OpenAI-compatible server, `http://` is allowed with a key only for this Mac (`localhost`, `127.0.0.0/8`, `::1`); saving a key for any other `http://` address is refused, and a key already stored for one is not sent. It is never written to a project, a Tandem file, a project folder or a log. **Remove key** deletes the Keychain item. A model reply goes through the same `normalize_actions` and melody lock as the hosted mode. Saved settings apply only to requests `guarded_app` marked local; the hosted app ignores them. Anyone who can read the person's login Keychain (their macOS account) can read the key; macOS may ask to allow access when Python or the app changes.

**Model downloads in the Mac app (MODEL.1):** model files are downloaded only when the person asks, from the https URL pinned in `tandem_desktop/models.py`'s catalog, and kept only when their size and SHA-256 match the pin; a file that does not match is deleted and nothing is installed. Every file is hashed again before a model loads, so a file changed on disk is refused. The download and job routes exist only behind `guarded_app` (the launch secret, the app's own origin and host); the hosted app never imports the module. Model files are code-adjacent (a PyTorch checkpoint can run code when loaded unsafely), which is why the pin is a hash and not only a URL; each model that uses the runtime must load its weights without executing pickled code where the library allows it, and its catalog entry records the licence (LIC.1 decides which weights may be distributed).

**Voice separation (SEP.1):** the htdemucs weights are a safetensors file pinned to one commit of `adefossez/HTDemucs` on Hugging Face (URL, SHA-256, size) and checked by MODEL.1 before every load. They are read with safetensors, never with `torch.load`, so loading cannot run pickled code, and `load_htdemucs` accepts only the `demucs.htdemucs.HTDemucs` class from the file's metadata. `/api/desktop/separate` exists only behind `guarded_app` (launch secret, own origin and host), takes a WAV of up to 10 minutes under a 256 MB body cap, runs one separation at a time and keeps the stems of the last two in memory only. (Demucs' former download host, `dl.fbaipublicfiles.com`, served an expired TLS certificate on 2026-11-12; Tandem does not use it.)

**Backing band (GEN.2):** MusicGen-Melody's files are pinned to one commit of `facebook/musicgen-melody` (URL, SHA-256, size each) and checked by MODEL.1 before every load; only the safetensors weights are downloaded, never the repository's pickled `state_dict.bin` files, and transformers loads them with `local_files_only=True`, `use_safetensors=True` and `trust_remote_code=False`. The weights are licensed CC-BY-NC 4.0 (non-commercial use only): the window says so before the download and on every generated band, and LIC.1 must settle it before any distribution. `/api/desktop/band` exists only behind `guarded_app`, takes the style as one line of at most 200 printable characters, the tempo and key only in fixed formats, a WAV of up to 10 minutes under a 128 MB body cap (only the first 30 s is used), runs one generation at a time and keeps the last two bands in memory only.

**Band from the notes (MRT.1):** Magenta RealTime 2's small model is six files pinned to one commit of `google/magenta-realtime-2` (`models.MRT2_SMALL`: the exported MLX graph `mrt2_small.mlxfn`, its state as safetensors, and MusicCoCa's SentencePiece vocabulary and three TFLite models for a style in words; 1.04 GB), checked by MODEL.1 before every load. None is a pickle: the graph is loaded with `mx.import_function`, the state with `mx.load` from safetensors, the TFLite files by the TFLite interpreter; `HF_HUB_OFFLINE` is set to 1 outright (whatever the environment says) and the files are read only from the verified folder. The weights are CC-BY 4.0 (commercial use allowed with attribution, LIC.1) and the code Apache 2.0; the window names them before the download and on every band. `/api/desktop/band/notes` exists only behind `guarded_app`, takes the style under the same rules as the other band, at most 4096 notes (`{m, t, d}` only, MIDI 0-127, times within 10 minutes) under a 1 MB body cap, `drums` as 0 or 1, and shares the other band's one-at-a-time rule and two kept results. `magenta-rt` and `mlx` are installed only on Apple silicon (environment markers in `requirements-models.txt`) and bring JAX, flax, librosa and a TFLite runtime with them.

**Voice as an instrument (TIMBRE.1):** the RAVE models are pinned to one commit of `Intelligent-Instruments-Lab/rave-models` (URL, SHA-256, size each) and checked by MODEL.1 before every load. RAVE publishes its models only as TorchScript, so unlike SEP.1 and GEN.2 (safetensors only) they are loaded with `torch.jit.load`: a TorchScript archive holds TorchScript code, run by torch's own interpreter with no access to Python modules, and its constants are read by torch's restricted unpickler, not Python's `pickle`. The pin is what makes that acceptable: only the exact files reviewed for this change are ever loaded, and a changed upstream file fails the hash check instead of loading. `load_rave` also refuses a module without `encode`, `decode` and `forward` or at another sample rate. The models are CC-BY-NC 4.0 (non-commercial use only): the window says so before each download and on every instrument recording, and LIC.1 must settle them before any distribution. `/api/desktop/timbre` exists only behind `guarded_app`, takes only the instrument names it lists, and caps the recording at 10 minutes and 256 MB.

These are the rules the later optional web-app path of AI.4 and STORE.2c (parked) must meet:
- On the web path, a user's own AI or storage key is kept only in their browser and sent only to the provider they chose, never to the Tandem server. A browser test must prove it.
- Any script running on the page can read a key kept in the browser, so XSS or a malicious extension means key theft. Before any key is stored the app needs a strict Content Security Policy: no inline script that is not hashed (the studio script is inline today), no third-party script, and `connect-src` limited to the app, the providers in use and any backend URL or local Ollama address the user entered. The policy must still allow the page's inline styles (or move them out) and WebAssembly compilation (`wasm-unsafe-eval`) for on-device tuning (VOX.4).
- How long a key is kept follows ADR-009 by default (the tab session); remembering it longer is an explicit user choice with a warning.
- Model replies called from the browser are validated in the browser exactly as `normalize_actions` and melody lock do on the server, and checked against the same fixtures.
- Users should set their own spend limits at their provider. The Tandem spend guards (shared token, Upstash rate limits) protect only the hosted mode.
- Projects and recordings in IndexedDB/OPFS are readable by anyone using that browser profile; the shared-device advice above applies.

## Before enabling paid AI
These apply to the optional hosted mode (operator's key on Vercel), not to bring-your-own keys.

1. Set `TANDEM_ACCESS_TOKEN` to a strong random secret; set provider/model/key only on Vercel.
2. Configure provider budget/caps and alerts. Be aware shared access tokens can be copied or stolen.
3. Avoid logging audio, secrets or complete personal prompts.
4. Add authentication, per-user quotas, safe usage limits and abuse monitoring before public commercial launch.
5. Separate project ownership and persistent object storage if cloud saving is introduced.

## Content-Security-Policy (SEC.7)
`/` and `/capture` are sent with a Content-Security-Policy (`page_policy` in `tandem_backend.py`), defence in depth behind the XSS fix above. Scripts run only from this origin, from the page's one inline module script by its SHA-256 hash (read from the bytes sent, so an edited page never goes out with a stale hash, and taken after CR LF and a lone CR become LF, as the browser hashes it, so a checkout with Windows line ends still starts), from Blob URLs (the pitch and capture AudioWorklets are built from source in the page) and as WebAssembly (`'wasm-unsafe-eval'`, the WORLD tuner); there is no `'unsafe-inline'` or `'unsafe-eval'`, so an injected `<script>`, an inline event handler or a `javascript:` URL does not run (`e2e/test_csp.py`), and the whole e2e suite runs with the policy on. `object-src`, `base-uri`, `form-action` and `frame-ancestors` are `'none'`. Styles may be inline. `connect-src` is `'self'`, any `https:` origin and `http://localhost`/`http://127.0.0.1` on any port, because the API base in Settings is the person's to choose; so the policy limits what runs, not where a script that runs could send data. The Mac app's launch secret is added by a WebKit user script, which the page's policy does not govern. Both pages also carry an `ETag` and `Last-Modified`, and a matching `If-None-Match` gets 304 with the same headers, so the service worker's network-first fetch does not download an unchanged page again.

## Other safeguards
- Browser microphone access requires permission and HTTPS.
- Short clip, WAV-format and body-size limits are enforced and tested (`tests/test_api.py`); CPU cost of a maximum-size request has not been profiled on Vercel.
- No commercial plugin binaries or copyrighted sample libraries are redistributed.
- Run dependency/license/vulnerability reviews and independent privacy/security testing.
- Report discovered vulnerabilities privately to the repository owner instead of opening public issues with exploit details.
